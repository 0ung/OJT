📘 README.md – 결제 시스템 OOP 학습 과제 (신입 개발자용)
📌 과제 목적

이 프로젝트는 자바의 클래스, 상속, 추상 클래스, 오버라이딩, 다형성, 그리고
Object 메서드(toString, equals, hashCode) 를 직접 구현해보는 실습입니다.

제공된 템플릿은 구조만 존재하며, 모든 실제 기능은 직접 채워 넣어야 합니다.

📁 제공된 파일 구조
pay/
├── Payment.java              // 부모(추상) 클래스
├── CardPayment.java          // 자식 클래스 1
├── BankTransferPayment.java  // 자식 클래스 2
├── PointPayment.java         // 자식 클래스 3
├── PaymentService.java       // 결제 실행 담당
└── PaymentProcessor.java     // main (직접 작성)


모든 클래스에는 주석만 있고 구현이 비어 있습니다.
주석을 읽고 필요한 기능을 본인이 직접 작성해야 합니다.

✏️ 반드시 구현해야 하는 기능
### 1) Payment.java (부모 클래스)

결제 공통 흐름을 process() 안에 구성합니다.
흐름은 다음 순서대로 동작해야 합니다:

validate() → calculateFee() → complete()


validate() : 공통 검증 로직을 작성합니다.

calculateFee() : 추상 메서드이며, 자식 클래스가 반드시 구현합니다.

complete() : 결제가 성공했을 때 동작하도록 작성합니다.

toString() : 객체 정보를 보기 좋게 출력되도록 직접 작성합니다.

equals(), hashCode() :
두 결제가 같은 객체로 취급될 기준을 본인이 정해 구현합니다.

2) CardPayment / BankTransferPayment / PointPayment (자식 클래스)

각 클래스의 주석을 참고하여, 각 결제 방식의 고유 규칙을 채우세요.

예시(정답 아님):

CardPayment → 카드 타입별 수수료 차이

BankTransferPayment → 시간대 제한

PointPayment → 보유 포인트 검증

규칙과 로직은 본인이 직접 결정해서 작성해야 합니다.

3) PaymentService.java

한 개의 메서드로 모든 Payment 자식 객체를 처리해야 합니다.

다형성이 자연스럽게 동작하는 구조여야 합니다.

4) PaymentProcessor.java

직접 사용자 입력을 받아 Payment 객체를 생성하고
PaymentService 를 통해 결제를 실행하도록 작성합니다.

콘솔에서 실제 실행 가능한 프로그램 형태여야 합니다.

🧭 구현 순서(추천)

Payment.java 공통 흐름 완성

각 자식 클래스의 validate / calculateFee / complete 구현

toString / equals / hashCode 작성

PaymentService에서 결제 호출 구조 만들기

PaymentProcessor(main)에서 전체 프로그램 실행
